# 総合監査レポート「頑張ろうニッポン！」(git_car-game_test)

- 対象: index.html（435KB / 726行 / 関数119個、単一ファイルPWA）、manifest.json、BGM・効果音ファイル群
- 実施: 2026-11-27。公開版プレイテスト（4プレイ＋全画面確認）とソースコード全量読解の突き合わせ
- 詳細レポート: `car-game-audit-logic.md`（ゲームロジック編）、`car-game-audit-platform.md`（基盤編・全36件）

## 結論サマリー

1. **「スコア0問題」は当たり判定のバグではなかった。** 判定式は正常。原因は「倒すまで無得点・敵HP非表示・アーマーが弾を無言で吸収・軌道プレビューが敵まで届かない」というフィードバック設計と実質難易度の複合。直すべきは判定ではなく**見せ方**。
2. **即修正できる確定バグが2件**（ベスト表示の+1、ミッションバッジ）。
3. **サーバー側でしか確認できない重大候補が1件**：パスワードの保存方式（ハッシュ化されているか）。SupabaseのSQLを確認するまで未確認。
4. ログインの遅さは、直列の多段リクエスト＋タイムアウトなしが主因候補としてコードで裏付けられた。

### E. 認証・Supabase（基盤編より）

| # | 内容 | 重大度 |
|---|---|---|
| E1 | パスワードがカスタムRPCに平文で渡され、DB側のハッシュ化はクライアントから確認不能。**平文保存なら重大問題**。SupabaseのSQL Editorで register/login 関数の実装確認が必要（`crypt(..., gen_salt('bf'))` の有無）。なお失敗時の10分ロックは実装されている形跡あり | 重大（未確認） |
| E2 | ログイン1回で最大4往復の直列リクエスト（ensure→login→load_cloud→save_cloud）。fetchにタイムアウトが一切なく（AbortController 0件）、1件詰まれば「確認中...」が無期限に続く。15〜20秒の遅さの主因候補 | 中 |
| E3 | スコアはクライアント申告制。RPC側で妥当性検証がなければランキング改ざんが可能（サーバー側未確認） | 中 |
| E4 | セッション（refresh token含む）をlocalStorageに平文保存。現状は innerHTML/eval 使用0件でXSS面は小さいが、将来の改修で即リスク化 | 中 |
| E5 | 合言葉はサーバー照合でクライアント埋め込みなし（良い点）。ただし全員共通の単一コードで、漏洩時の変更はサーバー側作業のみ | 軽微 |
| E6 | 引き継ぎコードは base64＋弱いチェックサムのみで改ざん可能（コイン・XP水増し）。設計上の割り切りなら仕様として明記を | 軽微 |
