# Claude Code 指示書 v9: 改善バックログの修正（第1節・第2節）

前提: 対象は `docs/improvement-backlog.md` の第1節（不具合）と第2節（改善点）。
第3節（新機能）と第4節（フェーズC）は今回の対象外。サーバー側の修正（1-9 の
duplicated 対応、1-6 のシード期限6時間化）は `docs/supabase/phase-b3-backlog-fixes.sql`
で Muse が別途適用するので、端末側はそれに合わせて実装すること。
タスクは J1 → J6 の順に、タスクごとにコミットを分けること。

---

## J1. ガチャ表示の修正（1-1 / 1-2 / 1-9 / 1-10）

- 結果サマリー行を「NEW ○件 / コイン +○○」だけにする（「かけら」「万能かけら」の集計表示を削除）。
- 新規結果の描画（`gOutTxt` / `gOutLong` / `gName`）から到達不能な `shard` / `universal`
  分岐を削除する。**ただし履歴画面の `company_key==='universal' → 万能かけら` 表示は
  B2以前の記録用に正しいので残すこと。**
- サーバー変更に追随: `gacha_pull` の `duplicated` 応答にも `results`（outcome/coins 付き）と
  `coin_bonus` が含まれるようになる。duplicated のときは通常どおり結果カードを表示するが、
  **`coin_bonus` を端末コインに加算してはいけない**（二重加算防止）。
- 天井表示「あと○回」: サーバーの pity が読み込まれるまで数字を出さない
  （「読み込み中…」等にする）。同期前の初期値で 40 と表示されるのが問題。
  計算式 (40 - pity) 自体はサーバーの保証タイミングと整合しているので変更しない。

## J2. ドロップの統一と救済（1-13 / 1-5 / 2-2）

- `rdStart()` の条件から `(dif>0 && !dlyOn)` を外し、チュートリアル以外の全モードで
  `start_run_seed` を呼ぶ（ボス戦・国別ステージでもカウンタと演出を出す）。
- カウンタのピルはラン開始直後（シード到着前）から表示する。到着前は「◆ 0」相当の
  プレースホルダでよい。シード到着後の巻き取り処理は現行のまま。
- 結果画面: シードが取れなかったラン（`r.seed==null`）で `r.ruby > 0` のとき、
  ルビー行に「（ドロップ演出は通信の都合で省略されました）」を添える。
- ホームか結果画面に「本日のドロップ あと○個」を表示する
  （`ruby_balance` の `drops_today` から 60 - drops_today を計算。上限到達時はその旨）。

## J3. デイリーの公平性を文言どおりにする（1-8 / 2-1）

- デイリーモードでは敵のスポーン列を日付シードで全員共通にする。
  具体的にはスポーン系（`spawn()` / `mk()` が使う乱数）を、日付（JST の YYYYMMDD）から
  作ったシード付き乱数（xs32 系でよい）に切り替える。通常モード等では従来の
  `Math.random()` のまま。ダメージ計算などスポーン以外は対象外。
- 文言（「全員が同じ敵の並び」）は実装に合わせて現状のまま維持してよい。

## J4. 表示・UI の改善（1-14 / 2-9 / 2-10 / プレイテスト指摘）

- ロゴの見切れ対策: ボール内に IM ロゴを描く共通処理で、横長ロゴが円の内接矩形に
  収まるよう縮小する（Huawei、TOYOTA INDUSTRIES などで左右が切れている）。
  描画ヘルパー1箇所の修正で全画面に効かせること。
- ガチャ画面のラインナップアイコンを大きくする（現状約30pxで読みにくい。
  44px 以上、またはカード型レイアウトに）。
- 結果画面に比較情報を追加: そのモードの前回スコアとの差と、自己ベストとの差
  （前回スコアは端末にモード別で保存）。
- ホーム上部に「今日やること」の小まとめ: ログインボーナス受取済みか、
  デイリー残り回数、ルビー残高（J2 のドロップ残量と並べてよい）。
- クラウド/端末データの選択画面で、それぞれの最終プレイ日時を表示する
  （古いセーブの誤選択防止）。

## J5. 掃除と性能（1-3 / 1-4 / 1-12 / 2-5）

- 実装と食い違うコメントを直す: `NLV_COIN` 前後と `NCO` 定義部の「かけらはサーバーで
  消費」「所持・レベル・かけらはサーバーが正」等の記述を、現行（コインのみ）仕様に合わせる。
- `gst.sh` / `gst.univ` の保存・復元をやめる（`supplier_state` の該当フィールドは
  受け取っても保存しない）。既存の保存データにキーが残っていても無視されること。
- レベルアップ費用: 端末表 `NLV_COIN` は表示・事前判定用、差し引きはサーバーの
  `coin_cost` が正、という役割分担をコメントに明記する（動作は現行維持）。
- 描画性能: 繰り返し使うグラデーションの生成をキャッシュし、パーティクル等の
  ホットループでの `shadowBlur` 使用を抑える。**見た目を変えない内部最適化に限定**し、
  変更前後で極端に暗くなる/光らなくなる箇所がないよう注意する。

## J6. スコアキャップの明示（1-11 / 2-3）

- `run.capped` が立ったランは、結果画面に「スコア上限到達」と表示する
  （サーバー検証に弾かれないための安全上限である旨を短く添える）。
- キャップ定数（SCORE_SAFE_KILL / SCORE_SAFE_STAGE）は現行値のまま変更しない。

## 対象外（この指示書でやらないこと）

- 1-7（シードの事前計算可能性）: 友人間ゲームのため受容する。対応しない。
- 2-4（BGM 軽量化）: 実測で既に 64kbps のため再エンコードの効果はなく、
  サイズの主因は10分超の長尺トラックであること。短縮ループ化は音楽体験を
  変えるため、ユーザーの判断待ちとして手を付けない。
- バックログ第3節（新機能アイデア）と第4節（フェーズC）は別途指示があるまで実装しない。
