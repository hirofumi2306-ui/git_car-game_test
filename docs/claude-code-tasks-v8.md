# Claude Code 指示書 v8: ガチャ経済アップデートの端末側対応

前提: サーバー側は `docs/supabase/phase-b2-economy-update.sql` で変更される（Muse が別途適用）。
**この指示書は v7 の後に実施すること**（ガチャ結果表示に触れるため）。
サーバー変更の要点:

- ガチャ価格: 1回 **10** ルビー / 10連 **90** ルビー
- 排出率: ★1 30% / ★2 32% / ★3 20% / ★4 13% / ★5 5%
- レベルアップはコインのみに変更（かけら消費なし）。`level_up_supplier` の戻り値は
  `{ok, level, coin_cost}` のみになった
- ガチャ結果の `outcome` は `new` / `coins` の2種のみになった:
  - 重複入手 → その場でコイン変換（`coins` = ★×300）
  - ★1 → 社名なしで `company_key: 'coins'`, `coins: 300`（コイン+300）
  - `coin_bonus` はその回の変換コイン合計（従来どおり端末のコインに加算）
- 新 RPC `start_run_seed()` → `{ok, seed}`。プレイ中のルビードロップ表示を
  サーバー確定数と一致させるための乱数シード
- `submit_run` に任意パラメータ `p_seed` が追加された（従来の呼び出しも動作する）

## I1. 価格と確率の表示を更新

- ガチャ画面の価格表示をすべて新価格に: 1回 10ルビー / 10連 90ルビー
  （ボタン、確認ダイアログ、残高不足メッセージなど価格に触れる全箇所）。
- 確率表示（提供割合）を新確率に更新: ★1 30% / ★2 32% / ★3 20% / ★4 13% / ★5 5%。
- 数値はサーバーが正。端末側で価格や確率を再計算しない。

## I2. レベルアップ UI をコインのみに

- 新規12社の詳細・レベルアップ画面から、かけら所持数・必要かけら・万能かけらの表示を外す。
- レベルアップは「コイン ○○ でレベルアップ」のボタン1つにする
  （費用は Lv1→2: 200 / 2→3: 400 / 3→4: 700 / 4→5: 1100。表示は `level_up_supplier` の
  戻り値 `coin_cost` を正とし、ok のときだけ端末のコインを差し引く従来方式を維持）。
- `supplier_state` の `shards` / `universal_shards` は表示に使わない（受け取っても無視してよい）。
- ガチャ結果の表示を変更:
  - 重複 → 「コイン +○○ に変換」と表示（かけら表示はしない）
  - ★1 → ロゴや社名ではなく、コインアイコンで「コイン +300」と表示
  - v7 の演出（L2/L3）と矛盾しないよう、カードの文言だけ差し替える

## I3. プレイ中のルビードロップ演出

ドロップ自体は従来から存在する（撃破ごと4%、1プレイ上限10個・1日60個、サーバー付与）。
今回は「プレイ中に見える化」する。サーバーと同じ乱数を使うため、表示と確定数が一致する。

1. プレイ開始時に `start_run_seed()` を呼び、`seed`（uint32）を取得して保持する。
   取得に失敗した場合は演出なしで通常プレイしてよい（ドロップ付与はサーバーが従来抽選する）。
2. 敵を1体倒すごとに、以下の生成器を**ちょうど1回**進める（撃破以外では進めない）:

```js
function xs32(s) {              // s: uint32 → uint32
  s = (s ^ ((s << 13) >>> 0)) >>> 0;
  s = (s ^ (s >>> 17)) >>> 0;
  s = (s ^ ((s << 5) >>> 0)) >>> 0;
  return s >>> 0;
}
// state = seed から開始。撃破ごとに state = xs32(state) し、
// state % 100 < 4 ならその撃破でルビーがドロップした扱いにする
```

   この実装はサーバー側 `_xs32` と完全一致させること。書き換え・最適化をしない。
3. ドロップした瞬間の演出（目立たせる）:
   - 倒した敵の位置に赤いルビー（宝石型の図形＋白い光沢。絵文字は使わない）が出現し、
     一瞬大きく弾けてから、画面上部のルビー残高表示へ放物線を描いて飛んで吸い込まれる
   - 効果音 sparkle を鳴らす
   - 到着した瞬間、ルビー残高カウンターが一瞬拡大＋点滅し、「+1」が浮かんで消える
   - プレイ画面にルビー残高（このプレイでのドロップ数）を常時表示する
     （例: 上部に「◆ ×3」。ホームの総残高と混同しないラベル付けにする）
4. ドロップ表示は最大10個までで止める（サーバーの1プレイ上限と一致させる）。
   10個に達したら以降は生成器を進めても演出しない。
5. プレイ終了時は `submit_run` に `p_seed: seed` を追加して送る
   （seed が取れなかった場合は従来どおり p_seed なしで送る）。
   結果画面のルビー獲得数は従来どおりサーバーの戻り値 `ruby` を表示する。

## 制約（厳守）

- 確率・価格・ドロップ率（4%）・上限（10/日60）はサーバーが正。端末で勝手に変えない。
- xs32 の呼び出し回数が撃破数とずれる実装にしない（演出の都合で余分に進めない）。
- v7 のガチャ演出・ロゴ表示には文言差し替え（I2）以外で触れない。
- スマホ縦画面でカウンター表示が既存 UI と重ならないよう配置する。
- 実装は I1 → I2 → I3 の順に、タスクごとにコミットを分けること。
