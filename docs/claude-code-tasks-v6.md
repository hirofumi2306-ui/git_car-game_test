# Claude Code 実装指示書 v6 ― フェーズB（ガチャ本体・クライアント側）

対象: `index.html`。サーバー側は `docs/supabase/phase-b1-gacha.sql` の適用が前提
（適用は別途 Muse 側で行う。この指示書の着手前に適用完了の連絡を待つこと）。
進め方：**1タスク1コミット**、コミットメッセージにタスク番号（H1など）を含める。
ルビー・かけら・レベル（新会社分）はサーバーの戻り値が正。端末で抽選・加算しない。

## 前提となるサーバー仕様（phase-b1-gacha.sql）
- `gacha_pull(p_count, p_req)` … p_count は 1 か 10、p_req は端末生成の UUID（回ID）
  - 成功: `{ok:true, balance, pity, universal_shards, coin_bonus, results:[{rarity, company_key, outcome, coins?}]}`
    - outcome: `new`（新規解放）/ `shard`（かけら+1）/ `coins`（Lv5ダブりのコイン変換、coins の額が入る）/ `universal`（★1＝万能かけら+1、company_key は 'universal'）
  - 残高不足: `{ok:false, reason:'no_ruby', balance}`
  - 同じ p_req の再送は前回結果を `{duplicated:true}` で返す（二重課金なし）
- `level_up_supplier(p_company)` … かけらをサーバー消費（会社かけら→万能かけらの順）
  - 成功: `{ok:true, level, coin_cost, used_company, used_universal, shards_left, universal_left}`
  - 失敗: `{ok:false, reason:'shards'|'not_owned'|'max_level'|'unknown_company', ...}`
- `supplier_state()` → `{companies:[{company_key, shards, level}], universal_shards}`
- `gacha_history(p_limit)` → `{history:[{rarity, company_key, created_at}]}`（新しい順）
- `ruby_balance()`（フェーズA）で pity（★4+なしの連続回数）が取れる。天井表示は「あと 40 - pity 回」

## H1: ガチャ画面
- ガレージ画面の上部から入る導線を置く。ホームのルビー残高表示（G1）からも遷移できるようにする。
- 画面の要素：
  - ルビー残高（サーバー値）
  - 「1回 30ルビー」「10連 270ルビー」ボタン。残高不足のときは無効化
  - 排出率の表示：★5 1% / ★4 7% / ★3 17% / ★2 30% / ★1 45%（★1は万能かけら×1 と明記）
  - 天井の表示：「★4以上確定まで あと N 回」（N = 40 - pity）
  - ラインナップ（対象12社とレアリティ。H3 の会社データを参照）
  - 履歴ボタン → `gacha_history(20)` の一覧（会社名・★・日時）
- オフライン時は「通信できないため引けません」と表示してボタンを無効化する。
- デザインは既存のスペックシート風（ライト・ダーク両対応）に合わせる。

受け入れ条件：排出率と天井残数が常時見える。残高不足・オフラインで引けない。

## H2: 抽選の実行と演出・結果表示
- 引くたびに `crypto.randomUUID()` で回IDを生成し、`gacha_pull(count, req_id)` を呼ぶ。
- 通信タイムアウト時は**同じ回IDで再送**する（サーバーが冪等に処理する）。新しい回IDで引き直さない。
- 演出：スペックシート風カードがめくれる演出。★の数でカードの色と光り方を変え、★4・★5 は特別演出。スキップボタンあり。
- 結果一覧の表示：
  - `new` → 会社名＋「NEW」
  - `shard` → 会社名＋「かけら+1」
  - `coins` → 会社名＋「コイン+（額）」※Lv5ダブり変換
  - `universal` → 「万能かけら+1」
- `coin_bonus > 0` のときは、その額を端末のコイン残高に加算して保存する（コインは端末管理の既存方式どおり）。
- 残高・天井表示は戻り値の balance / pity で更新する。

受け入れ条件：10連で結果が10件出る。再送しても二重に引かれない。コイン変換分が残高に反映される。

| astemo | 日立Astemo | JP | 2 | 反発：壁で弾が跳ね返る回数を増やす |
| akebono | 曙ブレーキ | JP | 2 | 摩擦熱：当たった敵に継続ダメージ |
| advics | アドヴィックス | JP | 3 | 急停止：発射した弾を空中で止め、罠にする |

- 所持とレベルは `supplier_state()` が正（端末のセーブデータに新会社のレベルを持たない）。
- 未所持の会社は効果なし・ガレージでは未解放表示。レベルは効果の倍率に反映し、**Lv5 でも初期効果の3倍を超えない**。
- 既存サプライヤーの効果の仕組み（発動条件・重ねがけ）に接続する。既存のトヨタ系グループボーナスの対象にはしない。
- 効果の数値（倍率・持続時間など）の初期値は既存15社の同格効果と同水準に置き、定数に切り出して調整可能にする。
- 旭化成の「ゲージ」は必殺技ゲージ（S3）を指す。S3 未実装の状態で着手する場合は、ゲージ加算の接続点だけ用意し、S3 完了後に有効化する。

受け入れ条件：12社すべてが解放状態で効果を発揮し、未解放では発揮しない。図鑑／ガレージに12社が表示される。

## H4: サプライヤー詳細とレベルアップ
- 新会社の詳細表示に：所持かけら数、万能かけら数、次のレベルアップに必要なかけら数とコイン（Lv→必要かけら/コイン: 1→2枚/200、2→4枚/400、3→8枚/700、4→16枚/1100）を表示。
- レベルアップの手順（順序厳守）：
  1. 端末のコイン残高が coin_cost 以上か先に確認（不足ならボタンを無効化）
  2. `level_up_supplier(company_key)` を呼ぶ
  3. `ok:true` のときだけ、端末のコインから coin_cost を差し引いて保存する
  4. 表示は戻り値（level / shards_left / universal_left）で更新する
- `ok:false` のときはコインを差し引かない。理由に応じて表示する（かけら不足など）。

受け入れ条件：かけら（会社→万能の順）がサーバーで消費され、コインは成功時のみ減る。二重タップで二重に上がらない。
