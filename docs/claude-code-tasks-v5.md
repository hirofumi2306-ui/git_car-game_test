# Claude Code 実装指示書 v5 ― フェーズA（ルビー経済・クライアント側）

対象: `index.html`。サーバー側は `docs/supabase/phase-a1-ruby-foundation.sql` と
`phase-a2-submit-run-ruby.sql` が適用済みであることが前提（適用は Muse 側で実施）。
進め方：**1タスク1コミット**、コミットメッセージにタスク番号（G1など）を含める。
セーブデータ（SV）の形は変えない。ルビーの値は端末で計算・加算せず、必ずサーバーの戻り値を表示する。

## 前提となるサーバー仕様（適用済み）
- `ruby_balance()` → `{balance, drops_today, streak, pity, universal_shards, bonus_today}`（要ログイン＝acc()が通る状態）
- `claim_login_bonus()` → 1日1回。`{ok:true, granted, streak, balance}` / 既受取は `{ok:false, reason:'already', balance, streak}`
- `submit_run(...)` の戻り値が jsonb になった：`{ok:true, ruby:<今回付与数>, ruby_capped:<上限で切れたか>}`
  - ドロップはサーバーが撃破数から抽選して付与する（端末では数えない）。

## G1: ホーム画面にルビー残高を表示
- ログイン完了後（クラウド同期の完了タイミング）に `ruby_balance()` を呼び、コイン表示の隣にルビー残高を表示する。アイコンは深紅の宝石（既存の絵文字・画像資産の範囲で。なければ ◆ を深紅で）。
- 表示はキャッシュ→サーバー値の順で更新してよいが、最終表示はサーバーの `balance` と一致させる。
- 取得に失敗した場合は前回値を表示し、エラーで画面を止めない。

受け入れ条件：ログイン後に実残高と一致する数値がホームに出る。オフラインでは前回値が出て操作を妨げない。

## G2: ログインボーナスの受け取りポップアップ
- ログイン完了後に `claim_login_bonus()` を1回呼ぶ。
- `ok:true` のときだけポップアップを出す：例「ログインボーナス +3ルビー（3日連続）」。7日連続の回は +10 分を含む金額（granted の値）をそのまま表示し、「7日連続ボーナス！」の一文を添える。
- `ok:false (already)` のときは何も出さない。
- 受け取った分は G1 の残高表示にも反映する（戻り値の balance で更新）。

受け入れ条件：日付が変わって最初のログインでポップアップが出て、同日2回目のログインでは出ない。

## G3: 結果画面にルビー獲得数を表示
- スコア送信（submit_run）の戻り値 `ruby` を結果画面に表示する：「ルビー +N」。
- `ruby_capped:true` のときは「本日のドロップ上限に達しました」を併記する。
- 送信がオフラインで保留になった場合はルビー表示を出さない（付与は送信時にサーバーで決まるため）。

受け入れ条件：オンラインでプレイを終えると、結果画面にサーバーが付与した個数と一致する表示が出る。
