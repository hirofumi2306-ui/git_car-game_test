# コード監査レポート：ゲームロジック編

対象： `index.html`（PWAゲーム「頑張ろうニッポン！」単一ファイル）
監査範囲：得点・撃破・当たり判定、LIFE／ゲームオーバー、タイマー、ボス戦勝敗、モード間のベスト記録、結果画面計算、その他ロジック不整合
表記：行番号は `index.html` の行。各指摘は「重大度／根拠／内容／修正の方向性」。コードから断定できるものは、プレイテスト結果との符合からの推論はと明記する。

---

## 最重要：スコア0・撃破0問題の切り分け

### 結論
**当たり判定そのもののバグ（当たっても無効化される等）はコード上に見つからなかった。** スコア0は「キル制スコア」「複数ヒット必須の敵HP」「アーマーによる無効化」「HP非表示」「プレビューの射程不足」という仕様・難易度・フィードバック不足の複合で説明できる。

### 根拠
1. **スコアは撃破した瞬間にしか入らない**
- 根拠：`kill()`（542行）が通常得点の唯一の加算点で、`score += Math.round((10*e.mx + (combo>1? 5*combo: 0)) * DFx().sc)`。ダメージを与えただけでは1点も入らず、コンボも発生しない。他の加算はボス撃破ボーナス（495–496行）とチャレンジのステージクリア（563行）のみ。
2. **敵は1発では倒れない設計**
- 根拠：敵HPは `ET`（70–78行）でドイツ勢 hp=3（`mk()` 490行で AUDI は4）、90秒モードでは難易度倍率で ×1.2（後述）。自機の dmg は `BT`（59–67行）で大半が1（NISSAN 3、LEXUS 2、DAIHATSU 0.5）。テストアカウントの TOYOTA Lv10 でも dmg ≈ 2.7（`fire()` 532行の計算）でドイツ敵は2発必要。発射数が少なければ（ボス戦1回目は2発のみ）撃破0は十分起こり得る。
3. **グループスポーンの敵は「アーマー」が弾を丸ごと吸収する**
- 根拠：`spawn()`（516–517行）でグループ生成時に `e.ar = Math.min(2, w.length-1)`（最大2）。当たり処理（559行）では `e.ar>0` のときアーマーを1減らして弾を消滅させ、**HPダメージもスプラッシュも発生しない**。ドイツステージは `gps:[GP.VW]`（82行）を持ち、スポーンの40%がグループ（516行）なので、「集団に当てたのに何も起きない」体験が頻発する。
4. **通常敵にはHP表示が一切ない**
- 根拠：HPバー描画はボスのみ（634行）。通常敵は被弾時にフラッシュ（`e.fl`）するだけで、残りHPも「あと何発か」も分からない。ダメージが蓄積していてもプレイヤーには無反応に見える。
5. **軌道プレビューが敵まで届かない**
- 根拠：プレビュー描画（679行）の到達距離は `md = 70 + v.p*200`（最大270px、`simPath()` 625行）。発射位置 `sy()=H-135`（486行）から画面上部の敵までは通常600px以上あり、プレビューの点列は途中で途切れる。長距離では目測頼みになり、蛇行（ドイツは `zz`、BMW は速度1.45倍）する小さい的（r=23–36）に複数回当てるのは初見では難しい。
6. **当たり判定式自体は正常**
- 根拠：判定（559行）は `距離 < 弾半径*0.8 + 範囲ボーナス(b.gr) + 敵半径` という標準的な円判定で、条件の反転や座標系の取り違えは見当たらない。`b.hit` Set による同一敵への多段ヒット防止も妥当。シールド（VOLVO の `e.sh`、559行）や TESLA の回避（558行）など「当たってもダメージにならない」経路はすべて仕様として実装されている。

### 修正の方向性
- ダメージ可視化：通常敵にも簡易HPバー／HP割合の色変化／ヒット時のダメージ数字表示を追加する。
- スコア仕様の見直し：ヒット時の微加点、または撃破に至らなくても進捗が伝わるフィードバックを入れる。
- アーマーの可視化：アーマー持ちは見た目（枠色・鎖表示など）と「弾を防いだ」専用エフェクトを付け、無反応に見せない。
- プレビュー延長：到達距離を画面端まで伸ばすか、弱い引きでも敵の高さまで届く補助線を追加する。
- 初回向け調整：序盤ステージの敵HP・グループ出現率・アーマー付与を抑える。

## 個別指摘

### 結果画面「ベストまであと○○点」が常にベスト+1になる
- 根拠：結果画面描画（371行）`'ベストまであと ' + Math.max(0, r.prev - r.score + 1) + '点'`。式に `+1` が直接入っている。
- 内容：プレイテスト観測（ベスト3165・スコア0で「あと3166点」、ベスト13852で「あと13853点」）と完全に一致する。同点は新記録にならない（`endGame()` 111行 `r.newRec = score > old`）ため「超えるにはあと1点」という意図の可能性はあるが、初回プレイ（prev=0・score=0）でも「あと1点」と出るなど、表示として誤解を招く。
- 修正の方向性：意図が「タイまで」なら `r.prev - r.score` にし、文言を「ベストまで／あと○点で新記録」と分ける。意図が「更新まで」なら現式のままでもよいが、その場合は文言を「新記録まであと○点」に変えるべき。

### ベスト記録キーの難易度サフィックスが画面間で分裂している
- 根拠：キー生成 `bk()`（102行）は難易度 `dif>0` のとき `'_d'+dif` を付ける。プレイ中HUD（687行）・`endGame()`（111行）・記録送信（241行 `submitRun`）は `bk()` を使う。一方、モード選択の国別ボタン（335行）と記録画面の国別ベスト（358行）はサフィックスなしの `'c'+i` を直接読む。モード選択のチャレンジ／90秒カード（318行）は現在選択中の `dif` でサフィックスを付け直して読む。
- 内容：ハード／地獄で遊んだ記録は、記録画面と国選択画面では「存在しない」ように見える（ノーマルのベストが表示される）。画面ごとにベストが食い違う構造的要因。
- プレイテスト観測「HUD BEST 3185 vs 記録のドイツベスト 3165」について：`dif=0` の前提では両者は同一キー `'c1'`（ドイツ=STG[1]、81–89行）を参照するため、**この数値差そのものはコードだけでは再現できない**。候補は (a) プレイ時点で `SV.df` が 0 でなく HUD 側が `'c1_d1'` 等を読んだ、(b) クラウド同期 `applyCloud()`（268行）が `SV.best` を丸ごとクラウド側データで差し替えた、の2経路。
- 修正の方向性：ベスト表示は全画面で `bk()` 相当の単一アクセサに統一する。難易度別ベストを記録画面でも見せるなら、国別ベストに難易度切替を付ける。

### 「ノーマル」という語が3つの異なる意味で使われている
- 根拠：難易度名 `DF[0].n='ノーマル'`（134行）、ステージ名 `STG[0].nm='ノーマル'`（82行）、記録画面の「ノーマルBEST」＝ `SV.best.normal`（357行）でこれはチャレンジ（耐久）モードのベスト。ランキングのモード名も `'normal'`（283行）。
- 内容：プレイテストで観測された「チャレンジのベスト263957が『ノーマル』表記でボス戦と混同される」の直接原因。263957 はチャレンジのベストであり、ボス戦（国別）のベストとは別物だが、表示上は区別できない。
- 修正の方向性：記録画面のラベルを「チャレンジBEST」に改名し、難易度名・ステージ名との重複を避ける。

### 狙撃（snipe）がLIFEを短時間に蒸発させる
- 根拠：`mk()`（492行）でプレイ開始14秒後から一定確率で敵に `atk='snipe'` が付与される。`updFoes()` の発射サイクルを経て `foeFire()`（506行）が命中すると、鉄壁／バリアがない限り `lives--`。被弾後の無敵時間はなく、`hurt=.25` は画面の赤フラッシュ演出のみで防御効果を持たない。発射体はプレイヤー固定位置 `(sx(), sy())`（486行）を狙うため回避手段が実質ない。
- 内容：プレイテストで「発射2回でLIFEが残り1目盛りまで減り、理由が分からなかった」と観測された主因候補。複数スナイパーのサイクルが重なると数秒で複数ライフを失う。ゲームオーバー理由が表示されない問題と合わせ、理不尽感が強い。
- 修正の方向性：被弾時に短い無敵時間（例：1秒）を入れる、狙撃の同時発射数を制限する、被弾理由を結果画面に表示する（例：「狙撃×3／到達×2」）。

### ボス撃破時の全滅処理が kill() 経由で得点・コンボを加算する
- 根拠：`bossWin()`（495–496行）は他全敵の `hp=0` をセットし、`update()` の撃破処理ループ（563行付近）がそれら全てに `kill()` を呼ぶ。結果として画面内の敵全員分 `10*e.mx` 点とコンボ加算、`stk++`、ドロップ抽選まで発生する。
- 内容：チャレンジでは「ボスを倒したら残り全員分の得点も入る」状態で、スコア効率が跳ね上がる。意図した「全滅ボーナス」なら問題ないが、結果画面の撃破数にも全員分が計上される。
- 修正の方向性：意図でなければ、全滅させる敵は `e.dead=1` を直接立てて `kill()` を経由させない。意図的なら「全滅ボーナス」として明示表示する。

### ミッション受取バッジが永遠に表示されない
- 根拠：`claimable = () => false`（106行）。タブバーのバッジ判定（152行）は記録タブでこの関数を使うため、ミッション達成時もバッジが出ない。受取自体は記録画面のボタン（363行）とハンドラ（226行）で正常に機能する。
- 修正の方向性：`claimable` を `SV.m.some(m => m.p>=m.n &&!m.c)` に戻す。

### 90秒モードは開始直後から「ハード」相当の難易度で始まる
- 根拠：`DFx()`（137行）は time モードで `escD(1 + …)` を返し、開始時点から難易度インデックス1（ハード：敵HP×1.2、出現率×1.25、スコア×1.3）。後半45秒で地獄相当まで上昇する。
- 内容：モード選択画面にこの前提は表示されず、初めて触るプレイヤーには「敵が硬い」理由が分からない。スコア0問題の体感を悪化させている一因。
- 修正の方向性：モード説明に「時間経過で難易度上昇」と明記するか、開始難易度をノーマル相当に下げる。

### endGame のコイン倍率が終了時点のエスカレーション難易度で計算される
- 根拠：`endGame()`（111行）のコイン計算は `DFx().rw` を使うが、この時点では `state` はまだ `'play'` で、`DFx()`（137行）はチャレンジ／90秒では経過時間で上昇した倍率（最大で地獄の rw=2.5）を返す。
- 内容：難易度を「ノーマル固定」で選んでいても、長く生き残るほどコイン倍率が上がる。得点倍率 `sc` も同様に `kill()` 時点の値が使われるため、同一ラン内でも序盤と終盤で1撃破の価値が変わる。設計意図の可能性はあるが、画面上の難易度表示と一致しない。
- 修正の方向性：ラン開始時点の難易度倍率を `run` に固定して使うか、エスカレーション自体を仕様として明示する。

### TESLA回避の横移動がフレームレート依存
- 根拠：回避で付与された `e.vx` は敵移動処理で毎フレーム `e.vx *=.88` と減衰される（dt 換算でない）。120Hz 環境では 60Hz の半分の時間で減衰する。
- 修正の方向性：減衰を `Math.pow(.88, dt*60)` 形式に変える。

### ボス到達＝即敗北が画面上で説明されない
- 根拠：地上到達処理（565行）でボスは `lives=0` に直行する。通常敵到達（-1）と同じ見た目のままLIFEが全損し、結果画面にも理由が出ない。
- 修正の方向性：ボス到達時は専用演出と結果画面への理由表示を付ける。

## 事実確認：LIFE・タイマー・勝敗条件（コード確定）

- **LIFE**：初期値は `maxL() = 5 + SV.u.life`（102行、ガレージ強化で最大+2）。減少は (1) 敵の地上到達で -1（565行、バリアがあればバリア消費で無効）、(2) 狙撃命中で -1（506行）、(3) ボスの地上到達で即0（565行）。回復は heal アイテムのみ（`useItem()`）。
- **ゲームオーバー**：`update()` 末尾（571行）で `lives<=0` を判定し `endGame()`。90秒モードとデイリーは `timeLeft<=0` でも終了（546行）。
- **ボス戦（country）の勝利**：ノルマ `STG.q` 体撃破（ドイツは12）でボス出現（563行）。ボスHPは `(20 + 4*stage) * 難易度倍率`（494行）。撃破で `run.win=1` となり 0.5秒後に `endGame()`（`updFoes()` 内 `bossT` 処理）。ボスは7秒ごとに雑魚を2体召喚し（`updFoes()`）、HP半分で激怒する。
- **チャレンジ（normal）の構造**：50秒ごとにボス出現（547行、撃破してもゲームは続き次は+70秒後）。ノルマ達成でステージが自動進行し `+100*stage` 点（563行）。難易度は経過時間でノーマル→ハード→地獄へ自動エスカレーション（136–137行）。
- **90秒モード**：`timeLeft` は `startGame()`（110行）で90に設定され `update()` で減算。難易度は前述の通りハード相当から開始。
- **コンボ**：撃破ごとに加算、2.2秒以内に次を倒さないとリセット（`kill()` 542行、`update()` 546行）。被弾（狙撃・到達）でもリセット。10コンボごとに全体攻撃 `ultimate()` が発動。

## 総括

- スコア0問題は判定バグではなく、**「倒すまで無得点・無表示」というフィードバック設計と、複数ヒット＋アーマーが要求する実質難易度の複合**が原因と判断する。最優先の改善は判定の修正ではなく、HP可視化とアーマー可視化、プレビュー延長である。
- 確定バグとして直ちに直せるものは「ベストまであと○○点」の +1（371行）と、ミッションバッジの `claimable`（106行）。
- ベスト記録はキー生成自体は一貫しているが、**表示側のキー参照が画面ごとに異なる**ため、難易度を上げて遊ぶほど表示の食い違いが増える構造になっている。
